# Meridian Staff Records — School HR System

A staff-management web app for an international school with 4 campuses
(Phnom Penh Main, Phnom Penh Riverside, Siem Reap, Sihanoukville). It manages
**staff only** — teachers, registrars, admin, finance, IT, and support staff.
Student attendance and hardware (e.g. biometric/card scanners) are
intentionally out of scope; staff attendance is captured through the web
app itself (self check-in/out), no extra hardware required.

Stack: plain HTML/CSS/JavaScript frontend, PHP backend (PDO + MySQL), MySQL database.

## What's included

- **Staff Directory** — add/edit staff, search & filter by campus, department,
  role type, status. Each profile has tabs for Overview, Emergency Contact,
  Education, Contracts, Leave, and Work History.
- **Campuses / Departments / Positions** — manage the org structure across
  all 4 campuses, with salary bands per position.
- **Contracts** — record probation/permanent/internship contracts per staff
  member; a dashboard/Contracts page flags anything expiring within 60 days.
- **Leave Requests** — file, approve, or reject leave against configurable
  leave types (Annual, Sick, Maternity, Wedding, Unpaid).
- **Dashboard** — headcount by campus and by role type, pending leave count,
  expiring-contract count.
- **System Users & roles** — Admin, HR Manager, HR Assistant, Viewer. Admin
  and HR Manager see every campus; a user can also be scoped to a single
  campus so campus-level HR staff only see their own campus's people. A user
  can also be **linked to a staff record**, which is what lets that person
  check themselves in/out on the Attendance page.
- **Attendance** — any staff member with a linked login can check in/out
  from the app (flagged "Late" automatically once past the configured grace
  period). Admin/HR Manager/HR Assistant can view all staff for any date,
  and can add or correct records manually (e.g. for someone who forgot to
  check in).
- **Payroll (basic)** — a monthly report that takes each active staff
  member's base salary and deducts a per-day amount for unpaid absences and
  half-days (approved leave is not deducted). This is a working estimate for
  Accounting to review, not a full payroll engine (no tax/NSSF rules). CSV
  export is available.
- **Recruitment** — a public **careers.html** page (no login) lists all
  "Open" job postings and lets candidates apply with a CV upload (PDF/Word,
  5MB max). Admin/HR Manager post and manage jobs from inside the app;
  applications can be reviewed and moved through New → Reviewed →
  Shortlisted/Rejected/Hired.

## 1. Create the database

1. Create a MySQL database and import the schema:
   ```
   mysql -u root -p < database.sql
   ```
   This creates the `school_hr` database, all tables, the 4 campuses,
   sample departments/positions, and leave types. It does **not** create a
   login yet (see step 3).

## 2. Configure the database connection

Edit `config/db.php`:
```php
define('DB_HOST', 'localhost');
define('DB_NAME', 'school_hr');
define('DB_USER', 'root');
define('DB_PASS', '');
```

## 3. Create the first Admin login

Deploy the whole `hr-system` folder to your PHP server (Apache/Nginx +
PHP 7.4+ with the `pdo_mysql` extension), then open:

```
http://your-server/hr-system/setup_admin.php
```

This creates `admin` / `admin123` using PHP's own `password_hash()`
(needed because a bcrypt hash must be generated by the same PHP version
that will verify it). **Delete `setup_admin.php` immediately afterwards**
and change the password from inside the app if you add a user-profile
password change feature, or via the System Users screen.

## 4. Log in

Open `http://your-server/hr-system/login.html`, sign in, and you'll land on
`index.html`, the main app.

## Roles

| Role         | Can view                | Can edit staff/contracts/leave | Can manage org structure | Can manage users |
|--------------|--------------------------|:---:|:---:|:---:|
| Admin        | All campuses             | ✅  | ✅  | ✅  |
| HR Manager   | All campuses (default)   | ✅  | ✅  | —   |
| HR Assistant | Own campus (if scoped)   | ✅  | —   | —   |
| Viewer       | Own campus (if scoped)   | —   | —   | —   |

Scope a user to one campus from **System Users → Campus scope** so their
Staff Directory, Dashboard, and Leave lists only show that campus. Leave
"All campuses" selected for HR staff working across all 4 sites.

## Linking a login to a staff record (for Attendance)

Self check-in/out only works for logins tied to a staff record. From
**System Users**, edit (or create) a user and pick their name under
"Linked staff record". Admin/HR accounts that aren't teaching/support staff
themselves can be left unlinked — they'll still see the admin attendance
view, just without a personal check-in/out card.

## Payroll assumptions (read before demoing/deploying)

The Payroll report is intentionally simple:
- `per-day rate = base_salary / working_days` (working days is an editable
  assumption on the page, default 22).
- Unpaid absence and half-days are deducted; approved leave (from the Leave
  module) is **not** deducted, since it's assumed paid.
- No tax, NSSF, or other statutory deductions are calculated — treat the
  "Net total" as a starting figure for Accounting, not a final payslip.

## Extending it

The schema also anticipates (tables already exist, no UI yet):
- `work_history` — automatically logged whenever a staff member's campus,
  department, position, or salary changes via the edit form.
- Additional reference tables you may want to wire up later: work
  experience, skills, references, attachments — follow the same pattern as
  `staff_extra.php` (one small table keyed by `staff_id`).

## Security notes for going live

- Serve over HTTPS.
- Change the default admin password immediately, and delete `setup_admin.php`.
- Restrict `config/` from direct web access if your host doesn't already
  block dot-free `.php` includes (e.g. an `.htaccess`/`Deny` rule, or move
  it outside the web root and adjust the `require_once` paths).
- Set a strong, unique `DB_PASS` and create a MySQL user with access only to
  the `school_hr` database, rather than using `root`.
